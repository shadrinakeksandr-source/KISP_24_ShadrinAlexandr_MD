## Создание проекта

## Узнайте, как создать новый проект на Expo.

Expo — это фреймворк для React Native, упрощающий разработку приложений для Android и iOS. Наш фреймворк предоставляет маршрутизацию на основе файлов, стандартную библиотеку нативных модулей и многое другое. Expo — это проект с открытым исходным кодом и активным сообществом на GitHub и Discord.

Мы также разрабатываем Expo Application Services (EAS) — набор сервисов, дополняющих фреймворк Expo на каждом этапе процесса разработки.

    Только начинаете программировать? Вы можете создать свое первое приложение на Expo, используя AI-агента для написания кода, вместо того чтобы писать его вручную. Ознакомьтесь с руководством «Создание с помощью ИИ» (Build with AI). В нем описан процесс настройки с нуля.

Системные требования

    Node.js (LTS).
    Поддерживаются macOS, Windows (PowerShell и WSL 2) и Linux.

## Expo CLI

Expo CLI — это инструмент разработки, который устанавливается автоматически вместе с пакетом `expo` при создании нового проекта. Для его запуска можно использовать `npx` (инструмент для выполнения пакетов Node.js).

Он призван ускорить процесс разработки приложения. Например, первое взаимодействие с Expo CLI обычно происходит при запуске сервера разработки командой `npx expo start`.

### Ниже приведен список часто используемых команд Expo CLI:
Команда	Описание
`npx expo start`	Запускает сервер разработки (независимо от того, используете ли вы специальную сборку для разработки или Expo Go).
`npx expo prebuild`	Генерирует нативные директории Android и iOS с помощью функции Prebuild.
`npx expo run:android	`Компилирует нативное приложение Android локально.
`npx expo run:ios`	Компилирует нативное приложение iOS локально.
`npx expo install package-name`	Используется для установки новой библиотеки или для проверки и обновления конкретных библиотек в проекте (при добавлении опции `--fix`).
`npx expo lint`	Настраивает ESLint. Если ESLint уже настроен, эта команда выполняет проверку (linting) файлов проекта.

Вкратце, Expo CLI позволяет разрабатывать, компилировать и запускать приложение, а также выполнять другие задачи. Подробную информацию о доступных опциях и действиях можно найти в справочном руководстве по Expo CLI.
EAS CLI

EAS CLI используется для входа в учетную запись Expo и компиляции приложения с помощью различных сервисов EAS, таких как Build, Update или Submit. Этот инструмент также позволяет:

Expo Doctor

Expo Doctor — это инструмент командной строки для диагностики проблем в проекте Expo. Чтобы воспользоваться им, выполните следующую команду в корневом каталоге проекта:
Терминал
`npm`
`yarn`
`pnpm`
`bun`

npx expo-doctor

Эта команда выполняет проверку и анализ кодовой базы проекта на предмет распространенных проблем: ошибок в конфигурации приложения и файле `package.json`, несовместимости зависимостей, некорректных настроек в конфигурационных файлах, а также общего состояния проекта. По завершении проверки Expo Doctor выводит результаты.

Если Expo Doctor обнаружит проблему, он предоставит ее описание, а также рекомендации по устранению или информацию о том, где можно найти помощь.

По умолчанию Expo Doctor сверяет пакеты вашего проекта с данными из каталога React Native и проверяет синхронизацию свойств конфигурации приложения при наличии нативных директорий. Эти проверки можно настроить в файле `package.json` вашего проекта. Подробности см. в описании параметров `reactNativeDirectoryCheck` и `appConfigFieldsNotSyncedCheck`.

Также можно использовать команду `npx expo-doctor --help` для просмотра справочной информации.

Что делать, если я открываю проект с неподдерживаемой версией SDK?

При запуске в Expo Go проекта, созданного для неподдерживаемой версии SDK, вы увидите следующую ошибку:

Правильное решение зависит от того, используете ли вы устройство Android, физическое устройство iOS или симулятор. Ознакомьтесь с разделом «Troubleshoot an Expo Go version mismatch» (Устранение проблем с несовместимостью версий Expo Go), чтобы установить совместимую версию или обновить проект.

## Навигация в приложениях Expo и React Native

Узнайте о рекомендуемом подходе к внедрению навигации в проекты Expo и React Native.

В базовую библиотеку React Native не входит встроенное решение для навигации, поэтому вы можете выбрать ту библиотеку, которая лучше всего отвечает вашим потребностям. Для приложений на Expo и React Native выбор обычно стоит между React Navigation и Expo Router.
Зачем приложениям React Native нужна библиотека навигации

Ядро React Native включает базовые компоненты пользовательского интерфейса, обработку касаний, API устройства и сетевые функции, но не содержит (помимо прочего) средств для работы с хранилищем данных, камерой, картами, большинством датчиков устройства и навигацией! Эти задачи решаются с помощью библиотек, созданных сообществом.
React Navigation

React Navigation — это библиотека навигации на основе компонентов, широко используемая в экосистеме React Native. Она позволяет полностью программно создавать навигаторы различных типов (стековые, вкладочные и выдвижные панели), реализуя сложные сценарии переходов, кастомную анимацию и специфические для приложения паттерны взаимодействия (UX).

Библиотека обеспечивает внешний вид и поведение, характерные для конкретной платформы (с плавной анимацией и поддержкой жестов), предлагает унифицированную маршрутизацию для мобильных устройств и веба, автоматическую поддержку глубоких ссылок (deep links) и типизированные маршруты со статической конфигурацией, а также отличается высокой гибкостью настройки.

Expo Router (рекомендуется для проектов Expo)

Expo Router — это библиотека маршрутизации на основе файловой структуры для проектов Expo и React Native. Следуя соглашению об организации директории приложения, она преобразует файлы в маршруты и интегрируется с Expo (включая Expo CLI и процесс сборки) без дополнительной настройки. Библиотека также предоставляет такие возможности, как типизированные и динамические маршруты, ленивая сборка (lazy bundling) в режиме разработки, статическая отрисовка для веба и автоматическая поддержка глубоких ссылок.

## Основы Expo Router

Expo Router — это фреймворк маршрутизации на основе файлов для React Native и веб-приложений. Он управляет навигацией между экранами и использует одни и те же компоненты на нескольких платформах. Чтобы начать, нам нужно знать о следующих конвенциях:

Каталог приложений: Специальная директория, содержащая только маршруты и их макеты. Любые файлы, добавленные в эту директорию, становятся экраном внутри нашего нативного приложения и страницей в интернете. В стандартном шаблоне он расположен на src/app.
Корневая верстка: файл src/app/_layout.tsx. Он определяет общие элементы интерфейса, такие как заголовки и панели вкладок, чтобы они были согласованы между разными маршрутами.
Правила имён файлов: Имена индексных файлов, такие как index.tsx, совпадают с родительским каталогом и не добавляют сегмент пути. Например, файл index.tsx в каталоге src/app совпадает с маршрутом./
Файл маршрута экспортирует компонент React в качестве своего значения по умолчанию. Он может использовать либо , , , либо расширение..js.jsx.ts.tsx
Android, iOS и веб имеют единую навигационную структуру.

    translateY.value += event.changeY;

        {
          translateX: translateX.value,
        },
        {
          translateY: translateY.value,
        },
      ],
    };

      requestPermission();
    }
  }, []);

  const pickImageAsync = async () => {
    let result = await ImagePicker.launchImageLibraryAsync({
      mediaTypes: ['images'],
      allowsEditing: true,
      quality: 1,
    });

    if (!result.canceled) {
      setSelectedImage(result.assets[0].uri);
      setShowAppOptions(true);
    } else {
      alert('You did not select any image.');
    }
  };

  const onReset = () => {
    setShowAppOptions(false);
  };

  const onAddSticker = () => {
    setIsModalVisible(true);
  };

  const onModalClose = () => {
    setIsModalVisible(false);
  };

  const onSaveImageAsync = async () => {
    if (Platform.OS !== 'web') {
      try {
        const localUri = await captureRef(imageRef, {
          height: 440,
          quality: 1,
        });

        await MediaLibrary.saveToLibraryAsync(localUri);
        if (localUri) {
          alert('Saved!');
        }
      } catch (e) {
        console.log(e);
      }
    } else {
      try {
        const dataUrl = await domtoimage.toJpeg(imageRef.current, {
          quality: 0.95,
          width: 320,
          height: 440,
        });

        let link = document.createElement('a');
        link.download = 'sticker-smash.jpeg';
        link.href = dataUrl;
        link.click();
      } catch (e) {
        console.log(e);
      }
    }
  };

  return (
    <GestureHandlerRootView style={styles.container}>
      <View style={styles.imageContainer}>
        <View ref={imageRef} collapsable={false}>
          <ImageViewer imgSource={PlaceholderImage} selectedImage={selectedImage} />
          {pickedEmoji && <EmojiSticker imageSize={40} stickerSource={pickedEmoji} />}
        </View>
      </View>
      {showAppOptions ? (
        <View style={styles.optionsContainer}>
          <View style={styles.optionsRow}>
            <IconButton icon="refresh" label="Reset" onPress={onReset} />
            <CircleButton onPress={onAddSticker} />
            <IconButton icon="save-alt" label="Save" onPress={onSaveImageAsync} />
          </View>
        </View>
      ) : (
        <View style={styles.footerContainer}>
          <Button theme="primary" label="Choose a photo" onPress={pickImageAsync} />
          <Button label="Use this photo" onPress={() => setShowAppOptions(true)} />
        </View>
      )}
      <EmojiPicker isVisible={isModalVisible} onClose={onModalClose}>
        <EmojiList onSelect={setPickedEmoji} onCloseModal={onModalClose} />
      </EmojiPicker>
    </GestureHandlerRootView>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#25292e',
    alignItems: 'center',
  },
  imageContainer: {
    flex: 1,
  },
  footerContainer: {
    flex: 1 / 3,
    alignItems: 'center',
  },
  optionsContainer: {
    position: 'absolute',
    bottom: 80,
  },
  optionsRow: {
    alignItems: 'center',
    flexDirection: 'row',
  },
});
